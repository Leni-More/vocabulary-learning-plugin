# 词汇学习 · vocabulary-learning

> 在 IntelliJ IDEA 里背单词：打开侧边栏就能学，全离线，不依赖任何云服务。

一个把「背单词」塞进你的编程工作流的 IDEA 插件。到期该复习的单词会自动出现在侧边栏，
选词、作答、排期、进阶全部本地完成。

- **全离线**：没有账号、没有网络请求、没有云端同步，数据只存在本机 SQLite
- **词库自己选**：插件本体很小（80 KB），词库单独下载后导入，可以同时管理多本词书
- **纯队列驱动**：同一次学习里，「什么时候再出现」由队列位置决定，而不是等时钟

## 功能

| 功能 | 说明                                                                          |
|---|-------------------------------------------------------------------------------|
| 侧边栏学习 | 一次一张卡，显示答案展示音标、释义、例句、助记，可标记 **认识 / 模糊 / 忘记** |
| 今日队列 | 打开插件即自动加载当天到期的复习词，无需手动开始                              |
| 选词 | 一个多选列表，可手动勾选，也可填个数后「随机选」再自行增减                    |
| 词库导入 | 选择下载好的 NDJSON 词库文件导入，多本词书互不干扰                            |
| 复习排期 | 9 档递增间隔（1 天 → 180 天），按作答结果自动调整档位                         |
| 重学机制 | 答错不只是一次重来：必须连续答对若干次才算过关                                |
| 外观可调 | 字体大小 + 单词/释义/例句/助记四色，改完侧边栏立即刷新                        |

## 安装

### 1. 安装插件

从源码构建：

```bash
./gradlew buildPlugin
```

产物：`build/distributions/vocabulary-idea-plugin-<version>.zip`

在 IDEA 中安装：

1. `Settings` › `Plugins` › 右上角齿轮 › `Install Plugin from Disk…`
2. 选择上面生成的 zip
3. 重启 IDEA

### 2. 下载词库

插件**不包含词库**（词库体积大，单独分发）。请从下面的地址下载：

> **词库下载地址**：见项目介绍

下载得到的应该是一个 `.json` 文件，格式为**每行一个单词**（NDJSON）。

### 环境要求

- IDEA **2024.2**（build `242`）及以上
- 从源码构建需要 **JDK 21**
- 编译产物是 Java 21 字节码，所以装不进 2024.2 之前的 IDEA（那些版本跑在 JBR 17 上）

## 使用方式

1. 打开右侧的 **Vocab** 工具窗口。
2. 点 **导入词典**，选中你刚才下载的 `.json` 词库文件。
   导入期间会显示进度，几千个词通常几秒钟完成。
3. 点 **选择单词**，在列表里挑今天要学的词：
   - 在筛选框输入字母可以缩小列表；
   - 在 **个数** 里填要抽几个，点 **随机选** 随机勾选这么多个，之后仍可手动取消或补勾；
   - 点 **确定** 完成添加。
4. 回到侧边栏开始作答。同一张卡：

   | 按钮 | 含义 |
   |---|---|
   | 显示答案 | 先看释义/例句/助记再作答 |
   | 认识 | 想起来了 |
   | 模糊 | 想起来了但不确定 |
   | 忘记 | 完全没想起来 |

5. 答完的卡会自动按算法重新排期，队列里该回来的会回来（见下）。
6. 当天全部完成后显示「今日已全部完成」。

> **词书名**取自文件名（不含扩展名）。导入 `MyBook.json` 后，词书名就是 `MyBook`，
> 「选择单词」里看到的就是这一本。多本词书彼此独立。

## 系统规则

核心思想：**档位 = 间隔天数**，作答结果只做两件事——调整档位、决定这张卡在队列里的位置。

### 档位表

档位从 0 开始，间隔单调递增：

| 档位 | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
|---|---|---|---|---|---|---|---|---|---|
| 间隔 | 1 天 | 2 天 | 4 天 | 7 天 | 15 天 | 30 天 | 60 天 | 90 天 | 180 天 |

- 档位 8（180 天）是上限，答对后不再继续拉长。
- 每次复习成功后，`下次复习时间 = 现在 + 当前档位间隔`。

### 初见：第一次见到这个词

「初见」= **这个词从来没被作答过**（数据库里没有作答记录）。

这一步决定它落在哪一档，而不是从最低档往上爬：

| 第一反应 | 落到档位 | 多久后自动回来 |
|---|---|---|
| 认识 | 档 3 | **7 天** |
| 模糊 | 档 1 | **2 天** |
| 忘记 | 档 0 | **1 天** |

> 设计意图：立刻认识的词不该被浪费在「明天再来」；而完全不认识的词需要尽快再见到。

### 复习：这个词以前答过

| 反应 | 档位变化 | 结果 |
|---|---|---|
| 认识 | **前进 1 档** | 30 天档 → 60 天档 |
| 模糊 | **后退 2 档**，下限档 1（2 天） | 30 天档 → 7 天档 |
| 忘记 | **重置到档 0（1 天）** | 任何档位 → 1 天档 |

下限规则：

- 模糊最低停在 **档 1 = 2 天**；忘记最低就是 **档 0 = 1 天**。

###  对于当天的学习内容

模糊/忘记不只是降档，还会让该词在**当天队列里**再出现，并且需要**连续答对若干次**：

| 失败方式 | 需要再「认识」的次数 |
|---|----------------------|
| 模糊 | **2 次**             |
| 忘记 | **4 次**             |

规则细节：

- 每答对一次「认识」，剩余次数减 1；**减到 0 就移出本次队列**。
- 剩余次数只存在数据库里（`learning.relearn_left`），界面上不显示这个计数。
- **中途再次失败，次数按新答案重算**：例如忘记后补了 2 次认识（还剩 2 次），
  此时再点忘记 → 剩余次数回到 **4**。
- 重学期间**档位不再变动**（降档已经在失败那一次做完了）。
- 重学未完成时，这张卡在数据库里一直处于「到期」状态，所以**关掉插件再打开可以接着补**，
  次数不会清零。

### 队列位置规则

失败（模糊/忘记）后，卡片**往后推 5 位**：

```
剩余不足 5 张 → 直接放到队尾
```

本次会话的队列顺序：

```
[ 今天到期的复习词 + 需要重学的词 ]  +  [ 本次新添加的词 ]
                                        ↑ 新词追加在最后
```

同一个词**同一次会话内可以出现多次**（因为要补重学次数），直到次数用尽才移出队列。

### 完整例子

#### 例 1：初见就认识

| 时间 | 动作 | 结果 |
|---|---|---|
| 第 0 天 | 初见，点**认识** | 档 3 = 7 天；7 天后回来 |
| 第 7 天 | 复习，点**认识** | 档 4 = 15 天 |
| 第 22 天 | 复习，点**认识** | 档 5 = 30 天 |
| 第 52 天 | 复习，点**认识** | 档 6 = 60 天 |

#### 例 2：初见就忘记，补完重学

| 时间 | 动作 | 结果 |
|---|---|---|
| 第 0 天 | 初见，点**忘记** | 档 0 = 1 天；剩余 **4 次**；卡在队列里往后推 5 位 |
| 同一次会话 | 再次出现，点**认识** | 剩余 **3 次**，仍在队列里 |
| 同一次会话 | 再出现，点**认识** | 剩余 **2 次** |
| 同一次会话 | 再出现，点**认识** | 剩余 **1 次** |
| 同一次会话 | 再出现，点**认识** | 剩余 **0 次 → 移出本次队列**；1 天后（档 0）再来 |
| 第 1 天 | 复习，点**认识** | 档 1 = 2 天 |
| 第 3 天 | 复习，点**认识** | 档 2 = 4 天 |

> 注意每次「延长」都发生在答对之后，且**重学通过的次数不会让档位虚高**——
> 4 次认识只换来「结束重学」，不额外加档。

#### 例 3：已到长间隔又忘了

| 时间 | 动作 | 结果 |
|---|---|---|
| — | 某词稳定在档 5（30 天） | |
| 第 0 天 | 复习，点**模糊** | 后退 2 档 → 档 3 = 7 天；剩余 **2 次** |
| 同一次会话 | 答对 2 次认识 | 结束重学，档位仍是 3 |
| 第 7 天 | 复习，点**忘记** | 重置到档 0 = 1 天；剩余 **4 次** |
| 第 8 天 | 复习，点**认识** | 档 1 = 2 天 |

#### 例 4：重学中途又失败

| 动作 | 剩余次数 |
|---|---|
| 初见忘记 | 4 |
| 认识 | 3 |
| 忘记（💥 重新计） | **4** |
| 认识 | 3 |
| 模糊（💥 重新计） | **2** |
| 认识 | 1 |
| 认识 | 0 → 结束 |

## 设置

`Settings` › `Tools` › **vocabulary-learning**

| 分组 | 项 | 说明 |
|---|---|---|
| 学习 | 每日新词数量 | 预留给后续版本，当前选词数量由「选择单词」对话框里的数字决定 |
| 外观 | 字体大小 | 10–36，实时预览 |
| 外观 | 单词 / 释义 / 例句 / 助记颜色 | 支持直接填 `#RRGGBB`，也可用「选择…」调色板 |

- 点设置页的 **确定** 后，已打开的侧边栏**立即套用**新字体和颜色。
- 颜色值非法（比如输入到一半的 `#12`）时会回退到默认色，不会报错。
- 默认配色在 IDEA 暗色主题下会自动切换到对应的浅色版本。

## 数据存储

全部本地，**不做任何网络请求**。

| 内容 | 位置 |
|---|---|
| 单词与学习进度 | `~/.vocab-idea/vocab.db`（SQLite） |
| 界面设置 | IDEA 配置目录的 `vocab-sidecar.xml` |

数据库为 WAL 模式，写入按线程独立连接，读写不会互相阻塞。

### 表结构

```sql
CREATE TABLE words (
    voc_id      TEXT PRIMARY KEY,   -- 唯一 id，格式 local:<词书名>:<拼写>
    spelling    TEXT NOT NULL,
    phonetic    TEXT,               -- 音标
    meaning     TEXT,               -- 释义
    sentence    TEXT,               -- 例句
    sentence_cn TEXT,               -- 例句翻译
    remethod    TEXT                -- 助记
);

CREATE TABLE learning (
    voc_id         TEXT PRIMARY KEY REFERENCES words(voc_id),
    stage          INTEGER NOT NULL DEFAULT 0,  -- 档位
    next_review_at INTEGER NOT NULL,            -- 下次复习时间（毫秒）
    last_result    TEXT,                        -- 最后一次作答 KNOW/VAGUE/FORGET
    added_at       INTEGER NOT NULL,
    relearn_left   INTEGER NOT NULL DEFAULT 0   -- 还需答对的次数
);

CREATE INDEX idx_learning_next_review ON learning(next_review_at);
```

## 词库

当前使用的词库来源为[词库地址 https://github.com/kajweb/dict](https://github.com/kajweb/dict)

插件读取 **NDJSON**：**每行一个 JSON 对象**，字段遵循 [kajweb/dict](https://github.com/kajweb/dict) 的结构。

必需的只有一个字段：`headWord`（拼写）。其余为可选，缺失时卡片对应部分留空。

```json
{"headWord":"sensible","content":{"word":{"content":{
  "usphone":"'sɛnsəbl",
  "trans":[{"tranCn":"明智的；合乎情理的"}],
  "sentence":{"sentences":[{"sContent":"She seems very sensible.","sCn":"她看起来很明智。"}]},
  "remMethod":{"val":"sense（感觉）+ ible → 有感觉的 → 明智的"}
}}}}
```

| 字段路径 | 用途 |
|---|---|
| `headWord` | 拼写（**必需**） |
| `content.word.content.usphone` | 音标 |
| `content.word.content.trans[0].tranCn` | 释义（取第一条） |
| `content.word.content.sentence.sentences[0].sContent` | 例句（取第一条） |
| `content.word.content.sentence.sentences[0].sCn` | 例句翻译 |
| `content.word.content.remMethod.val` | 助记 |

### 常见格式问题

选文件时会**先检查格式**，不合格会直接告诉你原因，不会静默导入 0 个词：

| 你的文件 | 提示 |
|---|---|
| 一个 JSON 数组 `[{...},{...}]` | 「这个文件是一个 JSON 数组，本插件需要每行一个单词（NDJSON）。可以用 jq 转换：`jq -c '.[]' 你的文件.json > 新文件.json`」 |
| 一个完整的 JSON 对象 | 「这个文件是一个完整的 JSON 对象，不是每行一个单词（NDJSON）。」 |
| 空文件 | 「文件是空的，或者没有可读内容。」 |
| 有 JSON 但没有 `headWord` | 「…需要 kajweb/dict 格式的词库：每行一个 JSON，并且包含 headWord 字段。」 |

**转换示例**：把 JSON 数组转成 NDJSON

```bash
jq -c '.[]' my-words.json > my-words.ndjson
```

**词书名**：取自文件名（不含扩展名）。导入 `MyBook.json` 后，词书名就是 `MyBook`，
在「选择单词」里看到的就是这本。多本词书彼此独立，互不覆盖。

**编码**：必须是 **UTF-8**。非 UTF-8 的文件会导致中文释义显示为乱码。

> 插件不内置任何词库，因此也不随插件分发词库内容。若你在自己的发行版里附带词库，
> 请自行确认该词库内容的分发许可。

## 项目结构

```
src/main/kotlin/com/vocab/idea/
├── storage/
│   └── Db.kt                   # SQLite：每线程独立连接、WAL、事务、schema 迁移
├── study/
│   ├── Scheduler.kt            # 复习算法核心：档位表、进/退档、重学次数、队列位置
│   ├── WordBook.kt             # NDJSON 词库导入、按词书取词、加入学习队列
│   └── DictionaryFormat.kt     # 导入前的格式预检与错误提示
└── ui/
    ├── VocabToolWindowFactory.kt  # 侧边栏主面板（学习流程）
    ├── WordPickerDialog.kt        # 选词对话框（多选 + 随机选）
    ├── VocabSettings.kt           # 持久化设置
    ├── VocabSettingsConfigurable.kt # 设置页
    └── VocabPalette.kt            # 字体/颜色解析与应用

src/main/resources/
└── META-INF/plugin.xml         # 插件声明（不含词库）

src/test/kotlin/com/vocab/idea/  # 单元测试与集成测试

dictionaries/                   # 本地放词库的位置（已 gitignore，不打包）
gradle.properties.example       # 构建配置模板（复制为 gradle.properties）

```

队列位置）彼此独立，改规则时通常只需要动一个函数。

## 已知限制

- **词库需自行下载**：插件不内置词库，首次使用要先下载并导入（见 [安装](#安装)）。
- **暂无「每日新词数量」上限**：设置项已存在但尚未接入选词流程。
- **不自动跳过在学单词**：重学中的词会在当天队列里反复出现，这是刻意设计（要补重学次数）。
- **单机存储，无同步**：多台机器/多个 IDEA 实例各自独立，不共享进度。
- **词库只支持 NDJSON**：JSON 数组需先用 `jq` 转换（见上）。
- **未在暗色/亮色全主题下逐一验证视觉细节**。
